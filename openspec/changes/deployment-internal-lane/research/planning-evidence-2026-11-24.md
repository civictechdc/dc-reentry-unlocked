## Repository facts

### API (`apps/api`)

- Route set is exactly four paths, `GET` plus automatic `HEAD`:
  `/health`, `/units`, `/filters`, `/openapi.json`. No sub-paths or path
  parameters. CORS additionally registers `OPTIONS *`.
- Rate limiting (`apps/api/src/app.ts`): `@fastify/rate-limit` is registered
  with `global: false`, and `app.rateLimit()` is attached once as a root-level
  `onRequest` hook, so every request counts against one per-client budget.
  No `trustProxy`, no `keyGenerator` override.
- Runtime environment: `PORT` (3000), `HOST` (127.0.0.1), `LOG_LEVEL`,
  `API_CORS_ORIGINS` (exact origins, wildcard rejected at boot),
  `API_RATE_LIMIT_MAX` (100), `API_RATE_LIMIT_TIME_WINDOW_MS` (60000).
- No application code reads the client address or forwarded headers.

## Front-door behaviour (live probe, Caddy 2.11.9)

Run locally with plaintext HTTP on loopback, Basic Auth in front of one
echoing upstream. "Header" means `X-Robots-Tag: noindex, nofollow`.

| Configuration | 401 (no or wrong credentials) | 200 and upstream 404 / 429 / 500 |
| --- | --- | --- |
| Plain `header` directive, listed before `basic_auth` | header present | header present |
| Plain `header` directive, listed after `basic_auth` (default directive order) | header present | header present |
| Deferred header (`defer`) | **header absent** | header present |
| `route { basic_auth …; header … }` (literal order) | **header absent** | header present |

Also observed:

- An upstream's own `X-Robots-Tag` is NOT overwritten by the plain directive:
  both values reach the client. (Corrected 2026-11-25 — the first probe read
  only the first header line.) `header_down -X-Robots-Tag` on each proxy leg
  removes the upstream's copy, leaving exactly one header. A `header_down` set
  or add acts on the upstream's copy only and never replaces the plain
  directive's value.
- `path /units` matches `/units` and `/units?limit=5`, not `/units/123` or
  `/unitsXYZ`.
- The path and the `Host` header reach the upstream unchanged. Caddy sets
  `X-Forwarded-For`, `X-Forwarded-Proto`, and `X-Forwarded-Host`.
- A client-supplied `X-Forwarded-For` is dropped; the upstream sees one
  address, the real client. The same holds for client-supplied
  `X-Forwarded-Proto` and `X-Forwarded-Host`.
- The `Authorization` header reaches the upstream by default.
  `header_up -Authorization` removes it.
- 401 responses carry `WWW-Authenticate: Basic realm="restricted"`.

Documentation: <https://caddyserver.com/docs/caddyfile/directives/header>
("By default, header operations are performed immediately unless …
deferred"), <https://caddyserver.com/docs/automatic-https> (IP addresses
are served with self-signed certificates by default; public certificates
for IP addresses exist only from some CAs),
<https://caddyserver.com/docs/caddyfile/directives/reverse_proxy>.

## GitHub (live read-only queries and documentation)

- The repository is public, its default branch is `main`, and Actions is
  enabled.
- The repository's default `GITHUB_TOKEN` workflow permissions are read and
  **write**. Workflows must scope `permissions:` explicitly.
- No environments, repository variables, or repository secrets exist yet.
- `main` has no branch protection and one ruleset (`code_scanning`), so the
  release lane's own gates on the pinned commit are the only gate on `main`.
- Deployment branch policies are available for public repositories: "Only
  branches and tags that match your specified name patterns can deploy."
  The docs do not say whether a blocked run fails early or stalls.
- Scheduled workflows run the latest commit on the default branch and are
  best-effort. Re-runs keep the same commit. `GITHUB_RUN_ATTEMPT` starts at 1.
- A failed scheduled workflow is notified to "the user who initially
  created the workflow".
- Concurrency: "At most one job or workflow run can be pending" in a group;
  a newer queued run replaces the pending one.
- A job that references an environment creates a deployment record with
  `sha` and `environment`. Re-runs add records, so the list is an audit
  trail, not the current state.
- Retention for public repositories is 90 days for artifacts and logs.
- Pushing an image needs `packages: write`. Creating attestations needs
  `attestations: write` and `id-token: write`.
- `actions/attest-build-provenance` v4 is described as a wrapper, and
  `actions/attest-sbom` as deprecated, both in favour of `actions/attest`.
  Confirm the current actions when implementing.
- Docker `build-push-action`: provenance defaults to `mode=max` on public

## DNS and hosting (live lookups, 2026-11-24)

- `civictechdc.org` is delegated to two DNS providers at once, NS1
  (`nsone.net`) and Squarespace Domains DNS (`squarespacedns.com`). Both
  answer authoritatively with identical records, so a new record must
  exist in both before it is relied on.
- The apex publishes no CAA record, so Let's Encrypt is allowed.
- A Lightsail instance has a public IP address and no DNS name. The only
  auto-generated URL in Lightsail is the Container Service default domain.
  A Lightsail DNS zone requires a registered domain.
- A static IP has no cost while attached to an instance. Without one the
  public IP changes on every stop and restart.
- Prices read live from the account in us-east-1 earlier the same day:
  `micro_3_0` $7, `small_3_0` $12.
- `sslip.io` and `nip.io` are not on the Public Suffix List, and
  `duckdns.org` is. Let's Encrypt allows 50 certificates per registered
  domain per seven days as one global limit, so a name under a shared
  wildcard-DNS service competes with every other user of that service.

## Added 2026-11-25

### Front-door mechanics, second probe (Caddy 2.11.9, local)

- `import` inside a `basic_auth { … }` block loads an account file; the
  file validates and serves.
- `caddy validate --config <file> --adapter caddyfile` exits 0 for a valid
  file and 1 for an invalid one.
- `caddy hash-password` reads the password from stdin when `--plaintext`
  is not given, and prints a 60-character bcrypt hash.
- With the plain `header` directive, Caddy's own default 502 page (upstream
  down) carries the header. A `handle_errors` block is not needed for it.
- An `http://` redirect site with `redir … permanent` answers 301 and
  carries the header.
- Header pass-through on a proxy leg: a request `request-id` header reaches
  the upstream unchanged; an upstream response `x-request-id` reaches the
  client unchanged; `header_up -Authorization` removes the credentials.
  (Relevant because the API echoes `x-request-id` — `apps/api/src/app.ts`
  — with a server-generated id, and logs it as `reqId` next to the resolved
  client address.)

### GitHub

- `actions/attest` inputs: `sbom-path`, `subject-name`, `subject-digest`
  (`sha256:<hex>`). Attestations are stored through the GitHub API by
  default; registry push defaults to false; `create-storage-record: false`
  exists. Documented permissions: `id-token: write`, `contents: read`,
  `attestations: write`, `packages: write`.
- Dependent jobs are skipped after a failure unless a condition overrides
  it (`always()`).
- Rulesets: "only users with bypass permissions can push"; bypass actors
  include roles, teams, and GitHub Apps; `GITHUB_TOKEN` is a GitHub App
  installation token. By inference, a ruleset whose bypass list excludes
  the Actions app blocks workflow-token pushes to `main` while listed
  maintainers can still push. The documentation does not state the Actions
  case explicitly — confirm by rehearsal.

### Docker address pools

- Docker's default pools for user-defined networks include `172.17.0.0/16`
  and the `172.28.0.0/14` range, allocated as /16 blocks, plus
  `192.168.0.0/16` allocated as /20 blocks. A pinned Compose subnet should
  sit outside every default pool and outside the provider's VPC range.

Source: <https://docs.docker.com/engine/network/>.

### Behaviour-driven tooling (retrieved 2026-11-26)

- `playwright-bdd` 9.2.1 (released 2026-09-06) "converts BDD scenarios into
  native Playwright tests". It depends on Cucumber's component packages

  deduplication.

### Why the existing framework, not a second runner (retrieved 2026-11-26)

CucumberJS capabilities without a full equivalent in `playwright-bdd`
9.2.1: publishing to the hosted Cucumber Reports service; native
`--profile` bundles (Playwright projects serve instead); a retry filter
by tag; a true once-per-run `BeforeAll`/`AfterAll` (hooks are per worker,
with a documented workaround); and confirmed support in the official
Cucumber editor extension. Everything else checked has an equivalent,
including the four Cucumber report formats through `cucumberReporter()`.
A capability is marked "partial" or "missing" here only where the
documentation establishes the limit. The user chose to keep the existing
framework (2026-11-26).
