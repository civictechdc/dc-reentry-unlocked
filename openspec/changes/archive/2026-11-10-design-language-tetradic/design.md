# Design

## Context

`apps/web/src/app.css` has one flat `:root`, a light-only scheme, and semantic color consumers across nine components; typography, spacing, and pill radii remain mostly literal. `app.html` and `src/lib/map/map-config.ts` duplicate colors outside CSS. Motivation and audience are in `proposal.md`.
The existing axe scan covers the main desktop screen at serious/critical severity, not a token-pair contract. The Chromium/Firefox/WebKit matrix exists, but browser binary versions are unverified and `webkit-ci-fidelity/proposal.md` records three exceptions.

## Goals / Non-Goals

- Define a readable, reference-layered language with deterministic runtime parity and contrast contracts.
- Preserve component layout, behavior, availability/selection semantics, and verification-status semantics; retain one light theme.
- No Tailwind, APCA, CSS polyfills, exhaustive literal retrofit, or unrelated WebKit test repair.

## Decisions

**D1 — DESIGN.md owns code generation.** Per the superseding user decision (2026-11-10), `apps/web/DESIGN.md` is the token source of truth, using canonical section order and one YAML tree. Pin reviewed `@google/design.md` to exactly `0.4.0` in `apps/web/package.json` and the lockfile. Its `export --format css-vars` produces committed, fully generated `apps/web/src/generated/design-tokens.css`, imported first by hand-written `apps/web/src/app.css`; never splice output into hand-written token blocks. The exporter emits a single `:root` with colors/spacing/rounded, not typography, elevation, or components. Lint-only adoption is superseded; codegen removes duplicated values for supported families but makes alpha output format a build dependency. Upstream bumps require deliberate schema/rule/export/dependency review. Add the discovery pointer to root `AGENTS.md` during implementation; DESIGN.md contains no OpenSpec tracking references.

**D2 — Three layers, shallow public names.** Use flat, readable `colors` keys: primitives such as `blue-strong`, semantic aliases such as `accent: "{colors.blue-strong}"`, then `components.button-primary.backgroundColor: "{colors.accent}"` and `textColor: "{colors.ink-on-accent}"`. Separate entries describe hover/focus states. Keep the schema's `typography`, `spacing`, and `rounded` roots; put the existing shadow string at `components.elevation-raised.shadow`, explained under Elevation, rather than inventing an unsupported top-level key. Avoid opaque numerical palette names and duplicated component literals.
Use no exporter `--prefix`: names are `--color-{token}`, `--spacing-{step}`, and `--rounded-{role}`, with path dots flattened to hyphens. Author unique flat leaf names so `surface-raised`, `accent-hover`, and `badge-confirmed-bg` remain readable; avoid flattening collisions. Export resolves references to lowercase hex, so layering lives in DESIGN.md authoring, not runtime `var()` chains. Primitive color leaves are exported too; consumers use semantic names, not primitive names. Component entries govern recipes/contrast but generate no CSS variables. Narrow the mapping table to hand-written typography/shadow properties and static bridges; generated families need no parallel mapping inventory.

**D3 — Blue/orange plus green/magenta rectangle.** Fix OKLCH hue anchors at blue 250°, orange 70°, green 150°, magenta 330°: complementary pairs 250°/70° and 150°/330°. Blue preserves the primary-action identity; green/magenta give supporting accents without the square alternative's cooler green anchor at 160°. Hue geometry alone does not establish hierarchy: blue owns actions, other hues stay subordinate. Reject an arbitrary four-color palette because it lacks complementary structure. Use named `faint`, `soft`, `mid`, `strong`, `deep` ramps with L targets 0.97/0.90/0.72/0.48/0.32, fixed hue and starting C 0.10, reduced until in sRGB gamut; these are candidates, not contrast guarantees. Neutrals remain dominant; do not force every hue onto a live component merely to demonstrate the tetrad.
Pins remain availability data; highlight remains selection; confirmed/unverified badges remain verification status, never referral policy. Keep their current values and `--color-surface-warning` outside brand references, even where hues coincide. Supporting brand green/orange must not masquerade as status indicators; do not alias `colors.pin-exact` to `colors.accent` merely because both currently equal `#0b5fab`.

**D4 — Precomputed sRGB runtime, OKLCH authoring.** Record hue/ramp construction in DESIGN.md prose; store final opaque sRGB hex tokens in YAML and `:root`, including explicit hover/focus values. This keeps tool evaluation, canvas values, and WCAG math identical without runtime color conversion. CSS Snapshot 2026 §2.1 includes custom properties, `@supports`, and Color 4 (`oklch()`); §2.2 includes cascade-5 (`@layer`); Color 5 is §2.4 with §4 release exceptions for `color-mix()` and relative colors. Snapshot status is not adoption evidence: OKLCH/mix/layers/supports are widely available, relative colors/`@property`/`light-dark()` newly available, but this change needs none of them at runtime beyond custom properties. Reject `@layer` because partially layering global styles changes precedence against unlayered components; reject registered properties and dynamic color derivation as needless coupling.
For future modern assignments, require an sRGB base `:root` plus a real property-value guard such as `@supports (color: oklch(50% 0.1 250))`; never rely on an earlier property declaration to rescue an unsupported function substituted through `var()`. Test modern and fallback paths; unsupported engines get a plainer, legible theme, not polyfill JS. No guards are needed around this change's hex-only tokens.

**D5 — Generated space/shape, checked hand-written type/elevation.** Define the existing system font stack; typography roles `body` (1rem, line-height 1.45), `small` (0.875rem), and `heading` (1.25rem), with current weight/line-height values inventoried before replacing literals. Spacing keys `none`, `xs`, `sm`, `md`, `lg`, `xl`, `xxl` hold 0rem/0.25rem/0.5rem/0.75rem/1rem/1.5rem/2rem; rounded roles `control` and `pill` hold 6px and 999px. Export dimensions verbatim into `--spacing-*`, `--rounded-control`, and `--rounded-pill`; rename `--radius` consumers to `--rounded-control`. Hand-write `--font-family-body`, `--font-size-base`, `--font-size-small`, `--font-size-heading`, `--line-height-body`, and `--shadow` in app.css, drift-checked against DESIGN.md because the exporter omits these families. Retrofit body and repeated equal literals first; leave exceptional dimensions explicit. Retain `--font-size-base` (body already consumes it); retain pin-highlight/ring roles as generated `--color-pin-highlight`/`--color-pin-highlight-ring`, not dead tokens to delete.

**D6 — Explicit bridges, no browser-dependent token reader.** Add `apps/web/src/lib/map/map-colors.ts` with named opaque hex constants for map paints and bitmap RGB construction; `map-config.ts` consumes them. A bridge mapping checked against resolved DESIGN.md colors covers pin fill/strokes, label text/background/border, and bitmap channels. Preserve distinct label ink `#1f2937` as `colors.pin-label-ink` (exported `--color-pin-label-ink`) rather than silently changing it to `colors.ink`; name remaining label roles from their existing values. Check `apps/web/src/app.html` theme-color against `colors.accent`. Canvas cannot consume `var()`; checked bridge duplication is smaller and SSR-safe compared with computed-style reads or a second custom generator. Bitmap channels derive from constants, not another set of RGB literals.

**D7 — Four checks plus rendered evidence.** (a) Upstream `lint`: errors block (exit 1), warnings surface without failing (exit 0 otherwise). (b) Regenerate the committed CSS with the pinned exporter and require `git diff --exit-code -- apps/web/src/generated/design-tokens.css`, following the frozen-artifact precedent; verify the artifact is tracked so a missing/untracked file cannot pass silently. This replaces drift comparison for colors/spacing/rounded; no manual edits to generated CSS. (c) Narrow `scripts/check-design-tokens.mjs` to hand-written typography/shadow plus D6 bridges against DESIGN.md. Safely parse YAML as data (no execution/custom constructors), resolve references with cycle/missing-path errors, and compare normalized values. Missing/extra hand-written mappings, unsupported values, or hand-written overrides of generated names fail closed; no regex-only YAML parsing or network dependency. Fixture mutations prove YAML, hand-written CSS, bridge, and reference failures. (d) Blocking WCAG token-pair unit tests.
`apps/web/src/lib/design/token-contrast.test.ts` reads resolved source tokens and maintains an explicit role/state/adjacency matrix: ink and muted ink on every used surface, on-accent text in each action state, badges, map-label text, focus rings, selection outlines, and essential control/pin boundaries. Compute WCAG 2.x sRGB relative luminance without rounding thresholds: normal text ≥4.5:1; large text ≥3:1 only with ≥18pt regular/14pt bold evidence; essential non-text ≥3:1 against actual adjacent colors. Decorative `--color-line` is not an essential boundary; essential controls use a passing `--color-line-strong` or dedicated role. Map outlines/halos must be evaluated as rendered, not claimed to contrast with every arbitrary raster tile.
Upstream `contrast-ratio` is only a warning at fixed 4.5:1 for resolvable component background/text pairs; it cannot replace large-text, non-text, semantic-pair tests, or usage inventory. `orphaned-tokens` is advisory, not a strict unused-token detector. Keep axe and add state/fallback visual probes across the existing CI browser matrix, recording engine versions and not treating WebKit exceptions as coverage.

**D8 — Wire once, execute locally and in both CI entry points.** Add apps/web scripts `design:lint`, `design:export` (regenerate only), `design:export:check` (regenerate plus tracked-artifact/byte-identity checks), and `design:drift` (narrowed checker). Root `design:check` invokes lint, export-check, and drift; add explicit `pnpm design:check` steps after install in `.github/workflows/pr.yml` and `full.yml`. Contrast tests run through existing web Vitest/root `pnpm test`; retain visible CLI warnings. Mechanically rename roughly 120 `var()` uses across nine components plus app.css body/focus rules to exporter names; preserve rendered values and avoid legacy alias layers. Only regeneration writes files; the narrowed checker stays read-only. Do not add permissions, runtime packages, or agent-hook gates.

## Risks / Trade-offs

- [Taste/semantic collision] Four hues can confuse status → Neutrals dominate; status tokens stay independent; walkthrough audience reviews a candidate before palette activation.
- [False assurance] Linter warnings and main-screen axe omit important pairs/states → Blocking pair tests plus focused rendered keyboard, selected, hover, badge, and map-label checks; no blanket AA claim.
- [Alpha exporter] Output-format churn can break byte identity → Exact version pin; review exporter diffs and regenerated artifact on deliberate bumps.
- [Generated names] Flattened paths can be awkward or collide → Flat, unique, domain-readable YAML names; no prefix or compatibility-alias layer.
- [Split runtime families] Generated CSS and hand-written type/shadow/bridges can diverge → One DESIGN.md source, regeneration gate for supported families, narrowed mutation-tested drift checker for the rest.
- [Compatibility] Snapshot maturity does not prove installed engine behavior → Record actual CI browser versions; retain fallback doctrine and explicitly report WebKit coverage gaps.

## Migration Plan

1. Inventory existing values into DESIGN.md; pin tooling and establish lint, regeneration, narrowed drift, contrast tests, and CI wiring. Document any pre-existing failing essential pair; correct it explicitly rather than weakening a threshold.
2. Replace the old color/radius token block with the committed generated CSS import, retaining hand-written typography/shadow and `color-scheme: light`. Rename all consumers mechanically; introduce generated spacing/pill roles and checked map bridges. Preserve color hex values byte-identically (including distinct map-label values), layout, and behavior before any palette edits. Verify deterministic gates and browser matrix; **human verification:** review the generated artifact and before/after rendering before advancing.
3. Produce tetradic candidate primitives and narrowly scoped brand-role changes as a separate reviewable step within this change. **Human verification:** walkthrough audience approves palette and semantic distinction before activation; token-pair gates and focused cross-engine probes must pass. Exact approved ramp values are review outputs, not unattended implementer choices.
4. Re-run lint, regeneration byte-identity, narrowed drift, tests, and rendered checks on activated values. Roll back palette values in DESIGN.md and regenerate CSS independently of structure/tooling if audience review or regressions reject them; never patch generated output or drop contrast gates to make rollback pass.
